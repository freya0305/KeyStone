# KeyStone需要什么AI/机器学习 — 非技术解读

## 背景：为什么现在只是"Idea"而不是工程方案

当前产品文档描述了功能：
- 上传简历 → AI分析
- 粘贴 Job → AI匹配
- AI给出修改建议
- 追踪申请结果

但这些都写了"AI做"，没有说**AI具体怎么运作**。

举一个具体问题：
> "简历和Job描述做匹配" —— 这是什么意思？
> - 是把两段文字扔给大语言模型让它比较？
> - 还是从简历里提取技能标签，再从Job里提取技能标签，然后做比较？
> - 还是更复杂的东西？

**不同的方法，成本差 10-100 倍，可实现的功能也完全不同。**

---

## KeyStone需要处理的核心问题（按技术复杂度分类）

### 第一类：已经可以靠大语言模型解决 ✅

| 功能 | 现状 | 说明 |
|------|------|------|
| 简历结构提取 | 可以用LLM | 把PDF里的文字读出来，分成"教育经历"、"工作经历"等部分 |
| Job描述解析 | 可以用LLM | 从网页或文字里提取职位要求、硬技能、软技能 |
| 语法/表达润色 | 可以用LLM | "把你的工作描述改得更专业" |
| 基础建议生成 | 可以用LLM | "这个工作要求X技能，你的简历没提" |

**现状**：这类功能用 Claude Haiku + Sonnet 完全可以做，成本可控。

---

### 第二类：大语言模型可以做，但成本和延迟是问题 ⚠️

| 功能 | 用LLM做的问题 | 替代方案 |
|------|--------------|---------|
| **逐行简历建议** | 每行都调一次LLM，成本太高 | 需要"缓存"和"复用"机制 |
| **多版本对比** | 生成3个版本的建议，用户选 | 用更小的模型做排序 |
| **大规模匹配** | 1000个简历 vs 1000个Job | 不能逐个调LLM |

**关键洞察**：LLM是"通用天才"——什么都能做，但每次调用都贵。
当你要做100万次的时候，必须换策略。

---

### 第三类：LLM本身做不了，需要单独的机器学习系统 🔴

| 功能 | 为什么LLM不够 | 需要什么 |
|------|--------------|---------|
| **Outcome Prediction（预测哪个建议能提高回复率）** | LLM没有反馈数据 | 需要从历史数据学习的预测模型 |
| **个人简历画像（你的简历在市场中的位置）** | LLM不知道市场分布 | 需要聚类/分布分析模型 |
| **技能相似度计算（"项目管理"和"PMP"是不是同一技能）** | LLM的判断不一致 | 需要技能图谱或嵌入向量 |
| **AB测试建议效果（哪个版本真的更好）** | 需要统计模型 | 需要实验设计和统计推断 |

**这是数据积累到一定程度后才会出现的需求。**

---

## 什么是"机器学习"在这个产品里的三层含义

### 第一层：LLM调用（现在就能做）
```
用户上传简历 → 调用LLM → 返回分析结果
```
这是**规则驱动的调用**，不是真正的机器学习。
只是把大语言模型当工具用。

### 第二层：检索增强生成 RAG（3-6个月后需要）
```
用户上传Job → 从数据库里找相似Job的简历+建议历史 → LLM参考历史数据生成建议
```
这时开始有"学习"成分：
- 数据库里有1000条"这类Job+这类简历+这个建议→用户采纳了"
- 新的建议参考了这些历史

**RAG = 检索增强生成**：
不是让LLM凭空想，而是先检索相关内容，再让LLM基于这些内容生成。

### 第三层：真正的预测模型（6-18个月后）
```
历史数据够多了 → 训练预测模型 → 直接预测"这个建议有73%概率被采纳"
```
这是真正的机器学习：
- 从数据中学习规律
- 对没见过的输入做出预测

---

## 关键结论（给非技术人员的理解）

**你现在能做的**：
- 用LLM做简历解析、Job解析、基础建议
- 成本可控，效果可用

**你3-6个月后需要的**：
- 一个"简历-Job-建议-结果"的历史数据库
- 基于这个数据库的RAG系统（让LLM参考历史）
- 技能标签系统（把简历和Job里的技能标准化）

**你6-18个月后可能需要的**：
- 预测模型（预测哪个建议更好）
- 个性化排序（每个人看到的建议优先级不同）
- 市场基准（你的简历在同类申请者中的位置）

---

## 一个重要的认知转换

> **LLM = 厨师**
> **机器学习模型 = 食谱**

- LLM（厨师）：看到食材和需求，当场做出菜
- 机器学习模型（食谱）：从10000道菜的经验里，总结出"这类食材+这类做法=好吃"

KeyStone现在的方案全是"厨师"在干活。
当积累了10000条数据后，你可以有"食谱"——让预测更准、更快、更便宜。
