# Analysis 21 — User Activation Flow (First 5 Minutes)

> Phase 01 Analysis — 2026-04-29
> Question: What is the step-by-step first experience? How do we get users to "aha" in under 5 minutes?

---

## 核心结论

激活的定义是：**用户在第一次访问中看到针对自己简历和真实职位的具体改写建议**。这不是"完成注册"，不是"看到landing page"，而是"哦，这个建议我明天就可以用"的那一刻。整个流程必须在5分钟内完成，且首次使用无需注册。

---

## Part 1：激活"Aha时刻"定义

**"Aha时刻"的精确定义**：
> 用户看到至少1条关于自己简历、针对他们粘贴的真实JD的具体改写建议，且这条建议是他们第一次看到（不是generic advice）

**为什么这个定义重要**：
- 通用的"你的简历需要更多量化数据"= 没有价值（ChatGPT能做）
- "你在DBS申请风险分析岗，但你写'负责管理合规事务'。GLC面试官期望看到'主导XX制度合规改造，覆盖X个业务部门，达标率提升至X%'" = KeyStone独特价值

**"激活"的可量化指标**：用户在同一session中接受或修改至少1条建议。

---

## Part 2：第一次体验全流程地图

### 阶段0：到达（0:00）

**入口场景**（按频率排序）：
1. 朋友分享（"我用这个改了简历，回复率提升了"）
2. 大学career centre推荐
3. LinkedIn/Reddit/职场群自然传播
4. 搜索"SG resume tips"

**Landing page的一个目标**：让用户立刻开始，而非了解产品。

---

### 阶段1：立即进入（0:00 — 0:30）

**无注册门槛**

Landing page核心CTA：
> **"粘贴一个职位链接，看看你的简历哪里需要改"**
> [职位URL输入框] [上传简历]

备选方案：
> **"先试一次 — 不需要注册"**
> [开始] → 直接进入上传界面

**为什么无注册门槛**：
- SG用户对"注册才能看结果"已经产生抵抗
- 第一次价值展示必须在承诺之前
- 注册在完成第一次分析后引导（用户已有理由留下）

---

### 阶段2：简历上传（0:30 — 1:00）

**界面**：简洁拖拽区域

```
[  拖拽简历文件到这里  ]
   或
[  点击上传 PDF / Word  ]
   或
[  粘贴文本  ]

支持格式：PDF, DOCX, TXT（最大5MB）
```

**背后处理（用户看不到）**：
- 文件解析（PDF→文本）
- Content hash生成（缓存用）
- SG flags检测开始（NRIC、NS、照片）

**UX关键**：不要显示"分析中..."的loading indicator超过5秒。如果解析慢，先显示"上传成功"，让用户进行下一步。

---

### 阶段3：职位输入（1:00 — 1:30）

**与简历上传同步进行或紧接其后**：

```
你在申请哪个职位？

[  粘贴职位链接（MCF / JobStreet / LinkedIn）  ]
   或
[  直接粘贴职位描述文字  ]

提示：尝试你最想申请的那个职位
```

**URL解析进行中**：
- 提取公司名、职位名、要求、职责
- 识别雇主类型（GLC/MNC/政府/初创）
- 提取关键技能要求

**如果URL解析失败**：无缝fallback到文本模式，不打断用户

---

### 阶段4：分析等待（1:30 — 2:30）

**最多60秒的处理时间（目标<30秒）**

等待界面不能只是spinner，要展示有价值的信息：

```
正在分析你申请 [职位名] at [公司名] 的简历...

✓ 解析职位要求
✓ 识别雇主类型：[GLC / 银行 / 科技公司...]
⟳ 比对你的经历与岗位需求
⟳ 生成SG市场针对性建议

SG市场提示：[显示1条有趣的SG职场洞察，如"GLC面试官评分时很看重团队影响力，个人成就需要放在集体背景中"]
```

**等待时间管理**：
- <10秒：只显示spinner
- 10-30秒：显示进度步骤
- >30秒：提前展示简历分析结果（先显示），建议生成继续进行

---

### 阶段5：结果展示（2:30 — 5:00）

**这是Aha时刻发生的地方**

**布局（三栏或上下分割）**：

```
左/上：简历关键段落（原文）    中/右：改写建议区域

[工作经历 - XXX公司]
  • 负责管理合规事务         →  建议：
    [原文高亮]                   "主导2023年MAS合规升级项目，
                                  覆盖全行8个业务部门，达标率
                                  从83%提升至98%"
                                  
                                  理由：这家GLC的JD明确要求
                                  "quantified achievements"；
                                  你目前的描述没有任何数字
                                  
                                  [✓ 采用] [✗ 跳过] [✎ 修改]
```

**首屏必须看到**：
1. 职位匹配概述（Strong/Transferable/Addressable/Fundamental各几条）
2. **至少1条具体改写建议**（不是generic advice）
3. 建议理由（引用JD和雇主类型）

**免费用户**：首个JD的所有建议完整可见（这是关键——Free tier必须给完整体验一次）

---

### 阶段6：注册引导（4:00 — 5:00）

**在用户看到价值后才提示注册**

触发时机：
- 用户接受第一条建议 → "保存这些修改，下次继续"
- 用户查看第3条建议 → "创建账号保存你的分析"
- 用户要导出修改后的简历 → "保存你的工作 — 1分钟注册"

**注册方式**：
- 邮箱 + 手机号（SG mobile，SMS验证）
- Google OAuth（最低摩擦）

**注册后立刻**：
- 保存刚才的分析结果（不要丢失已完成的工作）
- 问一个问题："你主要在找什么类型的工作？" → 用于个性化
- 清楚说明：免费版可以继续分析其他职位（前3条建议可见）；Pro解锁无限

## Part 3：关键UX决策

### 决策1：先简历还是先JD？

**建议：先JD**

原因：
- 最近在积极投简历的用户脑中最清晰的是"哪个职位"，而不是"我的简历"
- "我现在在投XX职位"是进入产品的心理入口
- 先JD让用户在上传简历之前已经有上下文动机

**测试两种顺序**（A/B test）：这是值得测试的关键变量。

---

### 决策2：匹配评估先展示还是直接进建议？

**建议：两者同时展示，但建议在首屏**

原因：
- 用户来的目的是"改我的简历"，不是"评分我的匹配度"
- 匹配评估是帮助用户决定"值不值得花时间改"——对于已经决定申请的人，直接给建议更有价值

**布局**：左侧summary card（匹配概述），右侧主体（具体建议，默认展开第一条）

---

### 决策3：第一次体验是否需要引导Tour？

**不需要**。

原因：
- 产品足够简单：上传→贴JD→看建议
- Tour会延迟Aha时刻
- 建议的格式（原文→改写→理由）是自解释的

唯一的引导：第一条建议上方一行小字："← 这是你简历原文，→ 这是建议改写，附理由"

---

## Part 4：激活率目标

| 指标 | 目标 | 测量方式 |
|-----|-----|---------|
| Landing→上传简历 | 60% | 页面事件 |
| 上传→完成分析 | 75% | Session分析 |
| 分析→看到建议 | 90% | 建议展示事件 |
| 看到建议→接受至少1条 | 40% | Suggestion accept事件 |
| 接受建议→注册 | 50% | 注册事件（条件）|
| **整体：访客→注册** | **约13%** | 端到端漏斗 |
| **整体：注册→首次Pro付费** | **4-6%** | 转化漏斗（Day 30）|

---

## Part 5：最容易失去用户的时刻

1. **简历解析失败**：PDF格式问题、表格简历等。必须有优雅的降级方案（"我们解析失败了，请粘贴文本"）
2. **等待时间>60秒**：用户会放弃。强制目标<30秒
3. **第一条建议是generic advice**：如果建议不够具体（"量化你的成就"而非具体改写），用户不会看到价值
4. **注册门槛在看结果之前**：杀死转化
